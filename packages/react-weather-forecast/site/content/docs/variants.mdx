and the [Storybook](/storybook/index.html) has each variant with controls.

## Full card

The default: the place and its local time, the current temperature with a
°F/°C switch, the next hours (scrolling sideways) and one row per day.

<WeatherPreview />

```tsx
<WeatherForecast forecastDays={5} forecastHours={12} />
```

## Compact card

`compact` is a single 36px row: the place, the current temperature with the
°F / °C switch, today's high and low, the wind, a ticking clock with its zone,
the next sunrise or sunset, the next three days and the date, left to right. It never grows a second line.
When the container is too narrow for all of it, whole items drop off the end of
the row instead — the date first, then the later days — and each day keeps its
rainfall and peak wind as hover text. It takes its colours from the container,
so it suits a coloured or dark background.

<WeatherPreview compact scenario="stormy" />

```tsx
<WeatherForecast compact />
```

## Sunrise and sunset

Both cards show sunrise and sunset. They are computed on the device with
[SunCalc](https://www.npmjs.com/package/suncalc) from the location's
coordinates, so they need no request and work with every provider, and they
are shown in the location's own time zone.

The full card lists the next two events in order under the temperature, the
coming one in bold with a countdown, and adds `↑ sunrise ↓ sunset` to every
day. The compact card has room for one: the next sunrise or sunset, with the
other on hover. Near the poles, when neither happens in the next two days, the
card says **No sunset** (midnight sun) or **No sunrise** (polar night).

<WeatherPreview scenario="rainy" forecastDays={3} forecastHours={6} />

```tsx
<WeatherForecast />                     // on by default
<WeatherForecast showSunTimes={false} /> // turned off
```

The calculation is exported too: `getSunTimes(date, latitude, longitude)`,
`getNextSunEvent(now, latitude, longitude)` and
`getDaySunTimes('YYYY-MM-DD', latitude, longitude, timeZone)` return `Date`s, or
`null` for an event that does not happen.

## Units

`temperatureUnit` is `'fahrenheit'` (the default) or `'celsius'`; the switch on
the card toggles it after render. `windSpeedUnit` is `'mph'` (the default),
`'kmh'`, `'ms'` or `'kn'`.

<WeatherPreview scenario="rainy" temperatureUnit="celsius" windSpeedUnit="kmh" forecastDays={3} forecastHours={8} />

```tsx
<WeatherForecast temperatureUnit="celsius" windSpeedUnit="kmh" />
```

## Several locations

`locations` renders one card per place, each with its own clock and timezone.

<WeatherPreview multi compact />

```tsx
<WeatherForecast
  compact
  locations={[
    { label: 'Phoenix', latitude: 33.4484, longitude: -112.074, timezone: 'America/Phoenix' },
    { label: 'Seattle', latitude: 47.6062, longitude: -122.3321, timezone: 'America/Los_Angeles' },
  ]}
/>
```

## Custom style

`className` and `style` go on the card's root, after its own styles, so they
win.

```tsx
<WeatherForecast compact style={{ background: '#fef3c7', color: '#78350f' }} />
```

## When everything fails

The widget renders nothing while it loads, and keeps the last forecast on
screen if a refetch fails. Only when every provider failed, the cache is empty
and the reloads are spent does it show an error naming what each upstream said.

<WeatherPreview error />

```tsx
<WeatherForecast reloadAttempts={0} allowStaleCache={false} />
```
