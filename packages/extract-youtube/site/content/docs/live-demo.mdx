The live demo is at **[youtube.js.org/demo](/demo)**, and its Storybook is at **[youtube.js.org/storybook](/storybook/)**. Both are served by the Worker that serves these docs.

The site lives in the monorepo at `packages/extract-youtube/site`, inside the package it documents. It is one Cloudflare Worker that serves:

| Path | What |
| --- | --- |
| `/`, `/docs/*` | These docs: Fumadocs on vinext. |
| `/demo` | A React app. The **Library** tab shows `<VideoGrid />` and `<VideoList />` over `useVideoLibrary()`. The **Admin** tab (`/demo#admin`) shows `<VideoLibraryAdmin />` and `<VideoAvailabilityPanel />`. `<FloatingYouTubePlayer />` is mounted once for both. |
| `/api/transcript?videoId=` | `YouTubeTranscriptApi` from the main entry, answering the `{ snippets }` shape the player and transcript modal read. |
| `/api/library/*` | `createVideoLibraryHandler` from `extract-youtube/library`, the whole admin API. |
| `/api/demo` | Which of the modes below this deploy runs in. |
| `/storybook/` | The Storybook, built into the same static assets. |

`worker/index.ts` is the Worker's entry: it answers `/api/*` from `worker/api.ts` and hands every other request to the docs.

## Modes

The Worker picks how open its library is from what is configured:

| `ADMIN_TOKEN` secret | `DB` (D1) binding | Mode |
| --- | --- | --- |
| unset | unbound | **Sandbox.** Anyone can edit an in-memory copy of the library. It lives as long as the Worker isolate and resets on its own. |
| set | either | **Token.** Paste the token on the Admin tab. The client sends it as a bearer token. |
| unset | bound | **Read-only.** The library persists in D1, so nobody can edit it without a token. |

`YOUTUBE_API_KEY`, when set, turns on Resync and richer auto-fill. Without it, auto-fill uses oEmbed for the title and channel.

## Run it locally

```bash
bun install                      # from the monorepo root
cd packages/extract-youtube/site
bun run dev                      # the docs, /demo and its /api/*, on one port
bun run storybook                # Storybook on :6006
```

The site imports the package from `packages/extract-youtube/src` through Vite aliases, so an edit to a component shows up on the next reload with no package build. Under `bun run dev` the demo's API runs in Node; set `ADMIN_TOKEN` or `YOUTUBE_API_KEY` in the shell to try those modes. `bun run preview` runs the built Worker in workerd.

## Deploy your own

```bash
cd packages/extract-youtube/site
bun run build                    # the docs, the demo and the Worker, then the Storybook into dist/client/storybook
bunx wrangler deploy
```

Then, optionally:

```bash
bunx wrangler secret put ADMIN_TOKEN
bunx wrangler secret put YOUTUBE_API_KEY
bunx wrangler d1 create extract-youtube-demo   # and add the binding to wrangler.jsonc as DB
```

A D1 library is seeded with the demo videos on its first request, and its tables are created then too.

## The stories

Stories live in `packages/extract-youtube/site/stories`, one file per component. Each has a docs page built from the component's props and the descriptions in the file. The admin stories use `createLocalLibraryClient`, which runs the real handler in memory, so every button in them works.

| Group | Components |
| --- | --- |
| Grid | `VideoCard`, `StackedVideoCard`, `StackNav`, `VideoGrid`, `VideoList` |
| Admin | `VideoLibraryAdmin`, `VideoEditDialog`, `CustomFieldInput`, `VideoAvailabilityPanel` |
| Player | `FloatingYouTubePlayer`, `YouTubeTranscriptModal` |
