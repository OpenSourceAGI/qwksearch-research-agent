The site lives in the monorepo at `packages/extract-pdf/site`. It is one Cloudflare Worker that serves:

| Path | What |
| --- | --- |
| `/`, `/docs/*` | These docs: Fumadocs on vinext. |
| `/demo` | The demo page. The **PDF** tab calls `/api/convert`; the **Webpage** tab (`/demo#webpage`) calls `/api/extract`. |
| `/api/convert` | `convertPDFToHTML` from `extract-pdf`, text layer only. |
| `/api/enhance` | Forwards one rendered page image to a Granite Docling processor. |
| `/api/source?url=` | The PDF at `url`, so the browser can render flagged pages. |
| `/api/extract` | `extractContent` from `extract-webpage`. |
| `/api/health` | `{ status, maxPdfMb, ocr }`. |

`worker/index.ts` is the Worker's entry: it answers `/api/*` from `worker/api.ts` and hands every other request to the docs.

## The PDF API

```bash
# Upload a file
curl -F file=@paper.pdf https://YOUR-SITE/api/convert

# Raw PDF body, with page-number markers
curl -X POST -H 'Content-Type: application/pdf' --data-binary @paper.pdf \
  'https://YOUR-SITE/api/convert?addPageNumbers=true'

# Remote URL
curl 'https://YOUR-SITE/api/convert?url=https://arxiv.org/pdf/1706.03762'
```

The response:

```json
{
  "source": "https://arxiv.org/pdf/1706.03762",
  "status": "ready",
  "title": "…",
  "author": "…",
  "html": "<p id=\"page-1\">…",
  "bytes": 2215244,
  "ms": 1377,
  "ocr": {
    "needed": true,
    "pageCount": 15,
    "pagesNeedingOcr": [3, 7],
    "reasons": { "3": ["table-caption", "numeric-grid"], "7": ["sparse-text", "figure-caption"] },
    "enhance": null
  }
}
```

`ocr` is the text-layer scan: the pages that look scanned or carry tables and figures, and why. When pages were flagged and OCR is configured, `status` is `"ready_with_pending_ocr"` and `enhance` is `{ "endpoint": "/api/enhance", "maxPages": 10 }`.

Errors are `{ "error": "…" }` with 400 (bad input), 413 (too large), 422 (unparseable PDF) or 502 (the URL could not be fetched).

## The OCR follow-up

Workers have no canvas, so they cannot rasterize pages, and a vision model is far too slow to run inside a request anyway. The demo splits the work:

1. `POST /api/convert` returns the text-layer HTML at once, with the flagged pages.
2. The page renders only those pages to PNG in the browser with PDF.js. For a URL source it reads the PDF again through `/api/source`.
3. It sends each image to `POST /api/enhance` as `{ "page": 3, "imageBase64": "…" }`. The Worker forwards it to the Docling processor with its secrets and returns `{ page, html, ms }`.
4. The page swaps each OCR'd page into the result as `<section class="ocr-page" id="page-N">`, one at a time. A page whose OCR fails keeps its text-layer version.

To turn it on, deploy the [Docling Space](/docs/pdf/ocr#hosting-the-processor) and give the Worker its URL and token:

```bash
bunx wrangler secret put DOCLING_PROCESSOR_URL   # https://YOUR_HF_USERNAME-extract-pdf-docling.hf.space
bunx wrangler secret put DOCLING_API_TOKEN       # the Space's DOCLING_API_TOKEN secret
bunx wrangler secret put HF_SPACE_TOKEN          # private Space only: a Hugging Face read token
```

Without `DOCLING_PROCESSOR_URL` the demo still works and only reports which pages would benefit from OCR. Optional tuning variables: `DOCLING_MAX_PAGES` (10), `DOCLING_MAX_TOKENS` (1500) and `DOCLING_MAX_IMAGE_MB` (8).

## The webpage API

```bash
curl 'https://YOUR-SITE/api/extract?url=https://en.wikipedia.org/wiki/Web_scraping'

# HTML you already have; the URL makes links absolute and helps the citation
curl -X POST -H 'Content-Type: application/json' \
  -d '{"html": "<html>…</html>", "url": "https://example.com/post"}' https://YOUR-SITE/api/extract
```

The response is `extractContent`'s article plus where it came from: `{ input, ms, title, author, author_cite, date, source, cite, url, word_count, html }`. Flags `images`, `links` and `formatting` default to true. Pasted HTML is capped by `MAX_HTML_MB` (2).

## Run it locally

```bash
bun install                      # from the monorepo root
cd packages/extract-pdf/site
bun run dev                      # the docs, /demo and its /api/*, on one port
```

The site imports `extract-pdf`, `extract-webpage` and `extract-youtube` from their source through Vite aliases, so there is no package build first. Under `bun run dev` the API runs in Node, and its variables come from the shell, for example `DOCLING_PROCESSOR_URL=http://127.0.0.1:7860 DOCLING_API_TOKEN=local-test-token bun run dev`. `bun run preview` runs the built Worker in workerd.

## Deploy your own

```bash
cd packages/extract-pdf/site
bun run build
bunx wrangler deploy
```

PDF parsing is CPU-bound. On the Workers Free plan (10 ms of CPU per request) most real PDFs fail with error 1102; on the Paid plan uncomment `"limits": { "cpu_ms": 30000 }` in `wrangler.jsonc`. See [Running on Workers](/docs/pdf/workers).
