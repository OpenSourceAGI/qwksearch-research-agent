Follow-up to #42 — `packages/shadcn-settings/test/settings-field.test.tsx`'s 2 failing cases — fixed: the root cause wasn't a testing-library/jsdom quirk, it was a real controlled-input bug in `TextControl` (backing the `string`/`password`/`textarea` field variants). `onChange` is documented as optional ("optimistic... so controlled hosts can *mirror* the value"), but the input's displayed value was driven directly by the `value` prop; if a host doesn't wire `onChange` back into `value`, React's controlled input snapped back to the original value on every keystroke, so blur committed the stale value instead of what the user typed. `TextControl` now tracks a local `draft` state seeded from and re-synced to the external `value` (via a `useEffect` keyed on the resolved value), so typed edits are always visible and committed on blur regardless of whether the host mirrors `onChange`; external `value` changes (e.g. another field syncing state) still flow through. `select-field.tsx`/`switch-field.tsx` were unaffected — they commit the change value directly rather than re-reading the DOM later. See packages/shadcn-settings/src/components/fields/text-field.tsx. Tests: packages/shadcn-settings/test/settings-field.test.tsx (added 2 regression cases: typed text stays visible without a wired `onChange`, and the field still syncs when the external `value` changes). Root `bun run test` vs `cd apps/qwksearch-web && bun run test` (#12) — fixed, and the actual root cause was bigger than the version-mismatch symptom it was filed under: `vitest.workspace.ts` uses `defineWorkspace`, deprecated since Vitest 3.2 in favor of `test.projects` in a root `vitest.config.ts`. Because this repo had no root `vitest.config.ts` at all, Vitest additionally treated the bare repo root as its own implicit, unconfigured project — silently re-running test files that belonged to packages never intended for the shared root run (`packages/domain-rank`, `packages/extract-pdf`, `packages/extract-pdf-docling`, and `packages/extract-youtube`, none of which even use Vitest — they run `bun test`/`jest`), *and* re-running some already-registered `apps/qwksearch-web` files (e.g. `lib/notebooklm/__tests__/credentials.test.ts`, `app/api/config/__tests__/route.test.ts`, `app/api/agent/__tests__/{autocomplete,search}.test.ts`) under that bare config instead of the app's own `vitest.config.ts`, losing its `@` path alias, `research-agent-ui/*` aliases, and `environment: 'node'` setting — so `@/...`-mocked modules and aliased imports silently failed to resolve. Migrated to `vitest.config.mts` (`.mts` to avoid Vite's CJS/ESM config-loader warning, since root `package.json` has no `"type": "module"`) with an explicit `test.projects` list, which also fixed a stale entry (`packages/render-url-to-html-cloudflare`, a path that no longer exists) by pointing it at its actual current package, `packages/html-renderer-api`. One genuine, version-specific regression remained once files were running under their correct project config: `app/api/config/__tests__/route.test.ts` mocked `ModelRegistry`'s constructor with `vi.fn().mockImplementation(() => ({...}))` — Vitest 4 now correctly rejects calling an arrow function with `new` (arrow functions were never constructible in JS; Vitest 3's mock wrapper had silently tolerated it), so the three call sites were changed to `function () { return {...} }`. Net effect on `bun run test`: 32 failing test files / 67 failing tests → 14 failing test files / ~52 failing tests, all pre-existing and unrelated (tracked as #42/#43 below), verified individually to fail identically when run via each package's own `bun run test`. 10. Common typo detection/correction — added: `packages/research-agent-ui/src/lib/typo-correction.ts` exports `correctTypos(text)`, a pure function that corrects common English typos using the existing (previously unused) `misspelled-typos-8k.json` dataset. It only auto-applies the ~7.8k clean single-word/short-phrase entries from that dataset (filtering out noisy ones like usage notes and quoted code keywords), preserves original casing and whitespace/punctuation exactly, and — because a word is only corrected when everything but its leading/trailing punctuation is plain alphabetic text — leaves URLs, code-like tokens (`npm_run/recieve.sh`), and identifiers with embedded digits or symbols (`gpt-4`, `kimi-k2.5`) untouched. Wired into the search-box autocomplete handler (`packages/research-agent-ui/src/api/handlers/autocomplete.ts`, used by `apps/qwksearch-web/app/api/agent/autocomplete/route.ts`): when the query has a known typo, the corrected query is prepended to the `suggestions` array (deduped against existing suggestions), reusing the dropdown the search box already renders. Tests: `packages/research-agent-ui/test/typo-correction.test.ts` (word-level correction, casing, punctuation, whitespace, URL/code/digit exclusions, noisy-entry exclusions), plus new cases in `apps/qwksearch-web/app/api/agent/__tests__/autocomplete.test.ts` covering the handler wiring. Non-goals for this slice: multi-word phrase corrections beyond short (≤3 word) dictionary entries, and typo correction outside the search box (editor titles/commands/prompts) — tracked as a follow-up below.
